# Release verification requirements

1. A standalone public clone builds from documented pinned tools and contains complete source, original/licensed assets and Apache-2.0 licensing.

2. Verify the live browser WASM demo, linked native executable and genuine physical/Kiro footage before describing them as delivered.

3. Release bundles contain checksums, dependency licenses, runtime requirements and sample assets; keep diagnostics and personal recordings out of releases.

4. Before submission, publish a Pages walkthrough with real QEMU screenshots
   of verified installation, actual installer/app theming, installed reboot,
   fullscreen operation and maintenance. Document the candidate revision and
   media checksums. Do not label a mockup or an unverified theme as executed.

5. Publish the owner's reviewed Toshiba NB205 demonstration video or public
   link when supplied. Show the artwork-to-live-mirror and recovery sequence;
   label QEMU and physical evidence separately. Missing media remains a
   submission blocker. Verify deployed URLs, captions, accessibility and privacy
   before declaring the project ready to submit.
